01 / C++ · MY FIRST LANGUAGE
C++：第一门逼我「想清楚」的语言
main.cppg++ main.cpp -o main · 0 error · 0 warning
#include <iostream>
#include <string>
using namespace std;
int main() {
  // 从抄例子，到自己写
  string name = "me";
  int score[5] = {88,92,76,95,81};
  int sum = 0;
  for (int i = 0; i < 5; i++) {
    sum += score[i];
  }
  cout << name << " 平均分: " << sum / 5.0 << endl;
  return 0;
}
第一份自己写完并跑通的程序 ✓

01指针：名字背后是地址

变量不只是个名字，它住在内存的某个位置上。

02内存：自己申请自己还

管过内存，才知道「性能」不是一句空话。

03报错：把逻辑拆到最小

编译不过的时候，只能一行一行地问自己「为什么」。

C++ 难的不是语法，是它不允许你含糊。

02 / HTML + CSS
网页：把想法变成看得见的东西

01骨架 · HTML

标签决定结构，div 不是万能。用对 header / nav / article，页面才有语义。
踩过的坑：满屏 div 套 div，最后自己都看不懂。

02皮肤 · CSS

一套色板 + 一套间距 + Flex 布局，页面就有气质；留白比配色更决定档次。
踩过的坑：全靠 margin 硬推位置，一改就全乱。

03手感 · 调试

F12 是最好的老师：改一行、刷一下，立刻看到结果，这种反馈很容易上瘾。
踩过的坑：Console 里的红字当没看见。

localhost:5173/index.htmlF12
<header> 标题与导航
<nav> 目录链接
<article> 主体 A
<article> 主体 B
<footer> 页脚信息
网页最爽的是即时反馈——
写的每一行，都能被立刻看见。

03 / JAVASCRIPT · EVENT DRIVEN
JavaScript：让页面「活」起来
like.js一个点赞按钮 · 第一个「会动的」东西
const btn = document.querySelector('#like');
let count = 0;
btn.addEventListener('click', () => {
  count++;
  btn.textContent = '已赞 ' + count;
  btn.classList.add('active');
});
// 页面开始"听"我说话了
原来会「变」的页面，是事件驱动的——
不是刷新换图，而是页面自己记住状态。

变量与函数

把重复的动作收进一个盒子。

DOM 选择

先找到那个元素，才谈得上操作。

事件监听

用户做了什么，页面就跟着变。第一次觉得：页面在听我说话。

坑全局变量是万能胶

什么都往全局塞，改到后面自己都不知道谁在改它。

03 / THEORY · 工科生为什么也要读
习概与毛概：工科生为什么也要读

01习近平新时代中国特色社会主义思想概论

原以为是一堆要背的条文。后来发现它在回答一个问题——一个超大规模的国家，怎么判断方向、怎么排优先级。
对我：做项目也讲主次，先解决最要命的那个 bug，别在细节里打转。

02毛泽东思想和中国特色社会主义理论体系概论

原以为是历史事件加结论。后来发现「实事求是」「没有调查就没有发言权」，本身就是工程方法论。
对我：调 bug 之前先看日志、先复现，而不是靠猜。

「没有调查，
没有发言权。」——《反对本本主义》
工科生容易只关心「怎么实现」。这两门课补的恰好是另一半：为什么做、为谁做、值不值得做。想清楚这一层，技术选型才不会飘。
实事求是调查研究抓主要矛盾

PROJECT / BLOG · 1 个属于自己的网址
用 AI 做一个博客：从想法到上线
起因很朴素：笔记散在备忘录、Word、微信收藏里，找不到，也懒得整理。
01

先把「要什么」写下来

页面有哪几个、每页放什么、哪些字段必须显示，先列清楚再动手。

02

让 AI 出第一版骨架

结构、样式、路由都交给它，我只负责描述和验收——能跑起来就算过。

03

自己接管取舍

内容自己写，配色和间距自己定，看不懂的代码一律删掉重写。

04

部署上线，先能访问再说

不追求完美，先有一个能发给别人的地址，再慢慢迭代。

踩过的三个坑

01能跑 ≠ 好读

AI 给的代码能跑，但结构不一定好读，得自己重排一遍。

02变量化很重要

样式越改越乱，因为没有把颜色和间距统一成变量。

03先本地后上线

部署时的路径和域名最容易卡住，先在本地跑通再上线。

AI 不替我想清楚要什么，
但它能把想清楚的部分，十倍速做出来。

TAKEAWAYS / 03 · WHAT I KEEP
我真正学到的三件事
课表上完就结束了，但这三件事大概会一直带到工作里。它们都不在某本教材里，是踩坑踩出来的。

01先做出来，再做好

能跑的第一版，永远比完美的第零版有用——哪怕它很丑，哪怕只有三个页面。

02打通比堆砌重要

C++ 的逻辑、网页的结构、JS 的事件、Linux 的环境，说到底在讲同一件事：怎么把复杂拆小。

03用 AI，判断权不交出去

它负责快，我负责对不对。分不清这两件事，用久了只会退步。

如果只让我留一句话给刚入学的自己：
别等准备好，先动手。
